## 〇、先搞清这台要「接谁、走哪个通道」

克隆 qwen 机后**接入分为两大出口**，**一台机只能跑一种服务角色**（同一 llama-server 进程）：
- **Hermes qwen-思考档**：lama-server 需 `--reasoning on --reasoning-budget 2000`（甜区档），供 `hermes -p qwenthink chat`。/ 
- **codex 快档**：lama-server 需 `--reasoning off`。codex 走 /v1/responses，思考 on 时超时连不上。

> 决定新机的角色后，**写进 `start_clone<sm>.sh` 的启动参数**。clone2 系数据盘已带 `--reasoning on --reasoning-budget 2000`（Hermes 思考档）。

## 一、克隆后的 5 步核心工作（每台都要做）

### 1. 建 SSH 别名 + 免密
```bash
# 在 ~/.ssh/config 新增别名块（只增不改现有），HostName=connect.<region>.seetacloud.com，Port=<新端口>
ssh-copy-id 方式把 ~/.ssh/id_rsa_musetalk.pub 装入新机；验证 ssh <alias> 'echo ok'
```

### 2. 核对 GPU 架构 + 数据盘
```bash
ssh <alias> 'nvidia-smi --query-gpu=name,memory.total,compute_cap --format=csv,noheader'
# sm = major×10+minor（8.9→89，12.0→120）。vGPU 名不副实必须实测底层卡。
# 数据盘自 clone2 克隆则完全 OK：models/*.gguf + llama.cpp/build<sm> + start_clone89.sh + .api_keys
```

### 3. 起服务 + 等 health
```bash
ssh <alrelativeias> 'cd /root/autodl-tmp && nohup bash start_clone89.sh >/tmp/s 2>&1 &'
# 轮询 curl :6006/health 直到 {"status":"ok"}；nvidia-smi 显存 ~27.4GB
```

### 4. 拿公网 URL（唯一人工交接点）
在 AutoDL 控制台把实例 **端口 6006** 映射成公网自定义服务，得到 `https://u<xxx>.<region>.seetacloud.com:8443`。**此步必等用户提供**。

### 5. 三处登记地址（★★ 易漏）
克隆新机后，**三处必须登记/更新新机地址**，否则脱节：
| 登记点 | 位置 | 作用 |
|---|---|---|
| **switch 脚本 TARGETS** | `monitor/hermes_qwen_switch.py` 的 `TARGETS` 字典 | Hermes「开哪台连哪台」自动切换需认得新机公网 |
| **VPS 看门狗 TARGETS** | `/opt/qwen-watchdog/qwen_watchdog.sh` | 开机自启+崩溃自愈拉起需连上新机 |
| **~/.ssh/config 别名** | 步骤1 | SSH 直连 |

## 二、接入 Hermes（让 hermes-qwen 用新机）

### 两种模式（用哪种取决于用户意图）
- **A. 自动切换（推荐，2026-09-16 起）**：`hermes_qwen_switch.py` 探测在线 clone，选 200 的那台写回 `qwenthink` profile 的 base_url。**多台机时自动跟在线机走**。
  ```bash
  hermes-qwen              # 探测→选在线机→切→启动 hermes -p qwenthink chat
  hermes-qwen --scan       # 只看各机在线状态，不改不启
  hermes-qwen --set clone5 # 强制指到某台
  hermes-qwen --restore    # 从 .bak-switch 恢复 base_url
  ```
  脚本只改 `~/.hermes/profiles/qwenthink/config.yaml` 的 `providers.qwenthink.base_url` 一行（先备份），api_key/model/其它字段、全局 deepseek、tts/stst 全不动。
- **B. 静态指定（SKILL.md ⑦ 旧法）**：直接改 `qwenthink` profile base_url → 新机公网。适合单机固定。

> **克隆后必做**：把新机公网加进 `TARGETS`（见 §一.5 第 1 行）。漏了这个，自动切换认不出新机。

### 探测安全机制（重要事实）
AutoDL **已关机**机公网返回 **nginx 404**（快速，非超时）。脚本把非 200 一概判离线 → **不会误切到没开的机器**。只有真 `200 + llama JSON` 才算在线。

## 三、接入看门狗（★默认自动配）

**只要新机是 qwen 克隆，默认加进 VPS 看门狗，开机自启+崩溃自愈**，等用户申请。
```bash
ssh vps-aliyun  # 编辑 /opt/qwen-watchdog/qwen_watchdog.sh，TARGETS 数组追加：
#   "connect.<region>.seetacloud.com:<PORT>:root:/bin/bash /root/autodl-tmp/start_clone89.sh"   # clone<N>
systemctl restart qwen-watchdog && systemctl is-active qwen-watchdog
```
- **key 复用**：clone2 派生机都带 `qwen-watchdog@vps` 公钥（克隆带过来）。若非 clone2 派生，把 VPS 的 `/opt/qwen-watchdog/id_watchdog.pub` 加进新机 authorized_keys。
- **验证**：开机后 `journalctl -u qwen-watchdog -f` 应见 `[host] llama-server 未就绪，拉起...` → `已恢复`。
